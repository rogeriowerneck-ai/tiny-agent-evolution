# Stage 02 — Simple Chat

In Stage 01 we created a reproducible Python 3.12 runtime using Docker.

Now we connect that Python application to a Large Language Model.

## Goal

Create the smallest possible interactive chat application using:

- Python 3.12
- Ollama
- qwen3:8b
- HTTP
- JSON

At this stage there are still:

- no conversation history
- no tools
- no tool registry
- no agent loop
- no environment awareness

## Architecture

The application runs on the Jetson Nano, while the language model runs on
another machine.

    Jetson Nano                         Mac
    -----------                         ---

    Docker
      |
      v
    app.py
      |
      | HTTP / JSON
      +-------------------------------> Ollama
                                          |
                                          v
                                       qwen3:8b
                                          |
      <-----------------------------------+
      |
      v
    Assistant response

The application and the LLM do not need to run on the same machine.

## Talking to the LLM

Ollama exposes an HTTP API.

Our application sends a POST request to:

    /api/chat

with JSON similar to:

    {
        "model": "qwen3:8b",
        "messages": [
            {
                "role": "user",
                "content": "What is 2 + 2?"
            }
        ],
        "stream": false
    }

Ollama returns JSON containing the model response.

The application extracts:

    result["message"]["content"]

and displays it to the user.

## Why use urllib?

This stage uses Python's standard-library `urllib.request`.

We deliberately avoid:

- an Ollama SDK
- requests
- agent frameworks
- LLM frameworks

The purpose is to make it clear that communicating with an LLM can be as
simple as sending JSON over HTTP.

## The chat loop

The application repeatedly:

    1. reads user input
    2. sends it to the LLM
    3. receives the response
    4. prints the response

Conceptually:

    User
      |
      v
    input()
      |
      v
    HTTP request
      |
      v
    LLM
      |
      v
    HTTP response
      |
      v
    print()

## Build

    docker compose build

## Run

    docker compose run --rm tiny-agent

Type:

    exit

to stop the application.

## What works?

The model can answer ordinary questions.

For example:

    You: 2+2

    Assistant: 4

The exact wording may vary because responses are generated by the model.

## Limitation 1 — No conversation context

Try:

    You: My name is Rogerio.

and then:

    You: What is my name?

The model cannot reliably answer.

Why?

Because every request contains only the current message:

    "messages": [
        {
            "role": "user",
            "content": user_message
        }
    ]

The previous interaction is gone.

The model itself is not maintaining our application's conversation.

This can produce interesting results.

For example:

    You: My name is Rogerio.

followed by:

    You: Who am I?

may cause the model to interpret "Who am I?" as a philosophical question
because it never received the previous message.

This gives us our first problem to solve:

    How do we give the LLM conversation context?

## Limitation 2 — No environment awareness

Try asking:

    What system are you running on?

The model may describe itself, its architecture, or its training.

But it cannot inspect the Jetson Nano or the container running our
application.

The current architecture is:

    LLM
     |
     X
     |
    real system state

There is no mechanism connecting model reasoning to the environment.

This will eventually motivate tools.

## What happens if the LLM is unavailable?

The LLM runs on another machine.

Network failures, Ollama being stopped, or the model server being
unavailable should therefore not crash the chat application.

The application catches communication errors and reports them:

    Error: Could not reach the LLM: ...

The user can then continue using the program or exit normally.

## What we learned

An LLM application can be very small.

At its core we currently have:

    input
      |
      v
    JSON
      |
      v
    HTTP
      |
      v
    LLM
      |
      v
    JSON
      |
      v
    output

But connecting an application to an LLM does not automatically provide
memory, environment awareness, or agency.

## Is this an agent yet?

No.

We have an interactive LLM application — a simple chatbot.

The model receives a prompt and generates a response.

It cannot:

- remember previous turns
- inspect its environment
- choose actions in the environment
- execute tools
- observe the results of actions
- decide what to do next based on those results

Those capabilities will be introduced progressively.
